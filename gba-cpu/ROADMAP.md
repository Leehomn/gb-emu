# GBA 整机开发路线

目标是继续自研 Rust 核心，用开源测试 ROM 验证，并在桌面和网页运行可游玩的 GBA 程序。

| 顺序 | 设计 | 验收 |
|---|---|---|
| 1. 卡带存档 | 通过 ROM 存档库标识选择 SRAM、Flash 或 EEPROM，驱动程序共享原始存档接口。桌面正常退出时保存到 ROM 旁边 | 已测 Flash 编程、擦除与切换存储区、两种 EEPROM 经 DMA3 读写、同一存档文件复载 |
| 2. 音频 | FIFO 低水位由 DMA1/2 补数据，四路传统音源与 A/B 数字采样混合 | 已测 FIFO 低水位和中断、四路波形和声道、浏览器提交非静音采样。音频 PWM 和桌面播放待补 |
| 3. 显示与 CPU 精度 | 依据失败测试细化卡带读数据后取指、边界访存、显示取样与显存争用 | 修正卡带 DMA 的首次访问等待，时序组升至 **1834/2020**。显示同步 DMA 已验证第 2–161 行传输和第 162 行关闭。其余时序待对照实机 |
| 4. 整机与网页 | 同一 Rust 核心接入浏览器画布、按键、音频与独立存档 | [GitHub Pages 播放器](https://leehomn.github.io/gb-emu/gba-cpu/web/)已上线。Chrome 已测启动、键盘和触屏、音频与存档恢复。实际手机和商业卡带兼容性待验证 |

每阶段先跑独立测试，再跑完整回归。卡带类型识别需要兼顾已有 ROM，存档文件大小不匹配时报错。音频 DMA 复用普通 DMA 的周期和优先级，修改后必须复查 CPU 与显示回归。显示与 CPU 的时序修改尤其需要与真机测量或公开测试 ROM 的结果对比。

扫描线分段改为只合成新完成的区间，绿色交换会在边界补取配对像素，精灵仍按整行预算计时。本机 80 帧压力场景每行写入 12 次调色板，五次重复的每帧耗时中位数从 2.92 ms 降到 1.63 ms。六个 Tonc ROM 各 160 帧，逐帧画面数据汇总摘要一致。

Chrome 使用手机视口和四倍 CPU 降速运行 Tonc 的 `obj_aff`。限制单次追帧后，4 秒采样中的画面提交从约 12 次/秒升到 49 次/秒，核心运行速度约 49 帧/秒。另一次对比中，自适应音频将可测的队列排空次数由 28 降到 3，当时播放速度中位数约为原速的 82%。正常速度组约 60 帧/秒，音频播放速度中位数为 100%。实际手机测试待做。

Mode 2 和 Mode 3–5 的背景显存等待由 CPU 和 DMA 共用。每种配置用公开 `ram-access-timing` ROM 测量 1,231 个位置，Mode 2 的 BG2、BG3、双背景分别有 486、488、974 个等待点，三种配置的旧版对照均为 0。Mode 3–5 各有 243 个等待点，间隔 4 拍。CPU 和 DMA 的独立测试覆盖双背景等待到 HBlank。

Mode 0 已通过同一 ROM 的五组测试，覆盖四个背景层、4bpp 与 8bpp，以及横向滚动 0、5、8 像素。五组分别记录到 93、155、94、155、93 个等待点，每个位置均与取数参考模型吻合。公开 ROM 运行在本项目的模拟器和开源替代 BIOS 上，待与真机逐拍对照。

Mode 1 混合背景已接入显存等待，自制 CPU 和 DMA 用例覆盖三层同时取数、32 位写入和消隐边界。上游公开显存时序 ROM 的背景菜单覆盖 Mode 0、2–5，Mode 1 尚待对照真机。

CPU 和 DMA 已共享精灵 OAM、精灵显存和调色板的等待模型。独立测试覆盖显示控制寄存器启用延迟、立即关闭、强制空白和行内显示结果。画面仍采用扫描线分段合成，实际的背景取数锁存、精灵像素缓冲与各类寄存器边界仍需逐拍真机对照。

公开显存时序 ROM 新增精灵 14 组、调色板 3 组及显示控制 4 组。精灵测试覆盖普通及仿射、两种色深、双倍尺寸、裁剪与 HBlank 空闲位。调色板测试中，背景底色、Mode 3 直接取色、Mode 3 混合底色分别记录 240、0、240 个等待点。显示控制测试分别记录背景启用、退出空白、精灵启用和精灵空白四组 DMA 计时。

本机用 Tonc 的 `obj_aff` 做三次 160 帧对照，模拟每帧耗时中位数从 3.29 ms 增至 3.67 ms，帧像素摘要一致。

可运行的小程序验证单个阶段。商业游戏能启动、能玩、能保存需要分别记录。

已验证自制 ARM 程序的 Mode 3 按键演示，以及扫描线、普通精灵、定时器级联、IRQ 进入和返回、VBlank DMA、音频 FIFO 和 SRAM 导出恢复。已使用独立汇编器验证自制 ARM/Thumb ROM 能调用函数并写出彩色图像。第三方 jsmolka ARM、Thumb 指令 ROM 均显示通过。已从卡带入口启动第三方开源 Pong，并验证进入对局后上下键能移动球拍。Mode 0 已用 Tonc 的 `sbb_reg` 验证启动和跨地图块滚动。后续用需要更多图形特效、BIOS 中断服务、音频与存档的开源 ROM 扩大验收范围。

Mode 1 和 Mode 2 的仿射背景已通过像素测试，自制 ARM 卡带验证了 R 肩键旋转。矩形窗口 WIN0 和 WIN1 已用 Tonc 的 `win_demo` 验证启动与方向键移动。窗口内外的亮度特效、目标图层和亮度系数已通过像素测试。补齐 Thumb `BX PC` 后，Tonc 的 `sbb_aff` 原版也已通过启动和 R 肩键旋转测试。

CPU 分开计算取指、数据访问和内部周期，按 ARM 或 Thumb 的取指宽度填充流水线。普通 DMA 按启动延迟、分次读写、收尾中断推进。纯内存 DMA 期间预取可继续，DMA 访问卡带时清空预取。测试覆盖预取完全命中、部分就绪和 DMA 结束后重新向卡带取指。开源替代 BIOS 下，普通 DMA 时序接入后 mGBA 时序组从 **1548/2020** 提升到 **1716/2020**，内存组从 **690/1552** 提升到 **1434/1552**，BIOS 数学组为 **603/615**。卡带预取与 DMA 交接更新后三组分数相同。预取最后一拍的卡带争用、部分内存边界和 BIOS 例程耗时仍有差异。任天堂原版 BIOS 的执行结果仍待验证。

修正 DMA1–3 读取 SRAM 及 DMA3 写入 SRAM 的字节总线行为后，内存组从 **1434/1552** 升至 **1482/1552**。时序组维持 **1726/2020**，BIOS 数学组为 **603/615**。

ARM/Thumb 的批量读写保留 SRAM 和镜像地址的低两位，由字节总线选择实际读写的位置。普通内存仍按 32 位对齐。修正后 mGBA 的 24 个 CpuSet/CpuFastSet 非对齐 SRAM 用例通过，内存组升至 **1506/1552**。其余失败集中在 BIOS 内容和 BIOS 例程访问未映射地址时的返回值，以及 DMA0 读取 SRAM 镜像所对应的 OAM 地址。

CPU 内部周期和 DMA 现在共用同一段时钟推进，后续取指或访存仍等待总线。乘法回归覆盖 DMA 在第一拍和第二拍内部运算开始时取得总线，以及 DMA 搬运完成后的取指恢复。显示控制 ROM 的计时包含 CPU 轮询，轮询耗时和后续 DMA 的行内起点也会随之改变。 [NanoBoyAdvance 内部周期参考](https://github.com/nba-emu/NanoBoyAdvance/blob/master/src/nba/src/bus/timing.cc#L7-L25)

卡带数据访问接管总线时，如果 CPU 请求的指令首个半字已经开始预取，就保留已等待的拍数。跳转重填流水线时从头取指。独立定时器用例覆盖 ARM、Thumb 及五种 `WAITCNT` 设置，公开套件时序从 **1726/2020** 提升到 **1778/2020**。

DMA 两端都位于卡带 ROM 时，首次读启动卡带总线访问，紧接着的写阶段沿用顺序等待。ROM 每个 128 KiB 块开头仍用首次访问等待。独立测试覆盖 16 位、32 位及块边界，公开套件时序从 **1778/2020** 提升到 **1834/2020**。 [NanoBoyAdvance DMA 总线参考](https://github.com/nba-emu/NanoBoyAdvance/blob/master/src/nba/src/hw/dma/dma.cc#L170-L190)

双层透明混合和半透明 4bpp 精灵已通过像素测试，Tonc 的 `bld_demo` 原版已验证混色模式切换和权重调整。

精灵窗口已通过像素测试，覆盖透明孔洞、翻转、多精灵形状合并、矩形窗口优先级和区域特效开关。已实现 Mode 5、Mode 3–5 位图仿射、8bpp 和仿射精灵、背景与精灵马赛克、单行精灵取样预算和绿色通道交换。Tonc 原版 `obj_aff` 与 `mos_demo` 已通过启动和交互验收。已验证行内分段取样及 HBlank DMA 对下一行的影响。
